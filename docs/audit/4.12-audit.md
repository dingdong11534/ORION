## 2. Section 3 Failure Reproductions & Root Causes (With Evidence)

Inspected actual persisted database `~/.local/share/orion/orion.db` (conversation `conv_a1dbf68df1f54f3284a1bf7a4fe19d0e`) and ran `ProductivityIntentInterpreter` / `ProductivityActionCoordinator` directly:

### 3.1 Task resolution, vague creation, and Today view
- **Observed DB state (`~/.local/share/orion/orion.db`):**
  - Only 1 task row existed: `('tsk_ad534f1c01f64b868228f6bcfab273d8', 'Complete coa unit 4 by 4pm', 'todo', 'medium', None, 1, '2026-11-27T05:25:13.192141Z', None)`.
  - Zero DBMS tasks existed.
- **Step 1:** `Make my DBMS task high priority.` → `ProductivityIntentInterpreter` returned `task_update(target='DBMS', priority=HIGH)`. `resolve_task_target('DBMS', tasks)` found no match → `I couldn't find an active task matching 'DBMS'.`
- **Step 2:** `add one as taask` → `ProductivityIntentInterpreter.interpret("add one as taask")` returned `ProductivityIntent.NONE` (regex only matched `task`, not `taask` or vague `add one as task`). `AssistantService` fell through to `qwen3:1.7b` with chat history, and Qwen3 **hallucinated**: `"Created task: **DBMS Unit 4**  \n**Priority:** High  \n**Details:** Complete the unit's content by 4 PM."` No row was written to `tasks`.
- **Step 3:** `Show me my tasks and habits for today.` → `ProductivityIntentInterpreter` returned `task_list(bucket='today')`. `ProductivityActionCoordinator` called `self._tasks.list_tasks(TaskFilter(bucket="today"))`, which filters strictly on `t_start <= r.due_at <= t_end` (`repository.py:197-204`). Because the only persisted task had `due_at=None` (and habits are never queried by `TASK_LIST`), it returned `"You have no active tasks for today."` — contradicting the actual DB and the Today view.
- **Additional root causes found:**
  - `target_resolver.py` has no edit-distance-1 typo tolerance for tokens ≥ 5 chars and does not strip Markdown syntax cleanly.
  - `ProductivityActionCoordinator` builds action card summaries from `task` returned by `create_task`/`update_task` rather than explicitly re-reading the persisted row after commit.
  - `TaskModel` stores `due_at` and `due_is_date_only`, and `TaskService.list_tasks` uses `self._clock.today()`, but `TASK_LIST` does not share a unified Today query function with the Productivity UI.

### 3.2 Duplicated input
- **Observed DB message:** `'I completed my reading today.I completed my reading today.'` → `"I couldn't find an active habit matching 'reading today.I completed my reading'."`
- **Root causes:**
  1. `productivity_intent.py:288` (`m_h_done`) uses greedy/unbounded `(.+?)` across sentence boundaries without splitting sentences first, so `"reading today.I completed my reading"` was extracted as the habit name.
  2. `Main.qml:209` `sendMessage()` checks `root.busy`, which is updated asynchronously via `orion.busyChanged` rather than guarded synchronously during submit; `Send` is not disabled during the submit transition, and no `client_request_id` UUID is generated per submit in QML/bridge.
  3. `ChatPage.qml:610` handles `Keys.onReturnPressed` only (misses numpad `Qt.Key_Enter` and does not guard against `inputMethodComposing` during IME composition).

### 3.3 Conversations
- **Observed DB state (`~/.local/share/orion/orion.db`):**
  - 4 rows in `conversations`, **all** titled `'New Conversation'`: 3 empty (`0` messages) and 1 active (`conv_a1dbf68df1f54f3284a1bf7a4fe19d0e`).
- **Root causes:**
  1. `Main.qml:764` `+ New Chat` button calls `orion.newConversation()`, which **does not exist** on `OrionBridge` (the Python slot is `createNewConversation()`).
  2. `AssistantService` never sets deterministic titles from the first user message.
  3. No check prevents creating duplicate empty conversations when the active conversation has 0 messages; no rename action or relative timestamp display exists.

### 3.4 Persisting conversational context
- `ProductivityContextStore` (`orion/application/productivity/productivity_context.py`) is an in-memory `dict[str, ProductivityConversationContext]`. All entity context is lost on restart, there is no `conversation_productivity_context` SQLite table, no list-of-up-to-10 IDs for ordinal resolution, and no 5-turn expiration rule.
